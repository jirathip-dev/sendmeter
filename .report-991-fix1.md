## The CI failure

`.github/workflows/ios-ci.yml` `package-tests` (`container: swift:6.3`,
ubuntu-latest) runs `swift test --package-path ios/App/SendLogWatchCore`; the
watch package depends on `sendlog-health-core`
(`ios/App/SendLogWatchCore/Package.swift:19`), so the whole SendLogHealthCore
module must compile on Linux. At head `44c9e33` it failed with
`cannot find type 'CFString' in scope` (ReadinessWidgetContract.swift:197-203)
— Linux Foundation ships no CoreFoundation, and #991's fix compiled the
CoreFoundation access unconditionally.

## The fix — platform split

- `ReadinessWidgetAppGroupDefaults` (the CFPreferences accessor) is now
  compiled only inside `#if canImport(CoreFoundation)` in
  `ReadinessWidgetContract.swift`. `canImport(CoreFoundation)` is false on
  Linux (the CI error itself is the evidence: `CFString`/CFPreferences did not
  resolve in the swift:6.3 image) and true on Apple platforms (the same guard
  compiles the accessor in every macOS build here — `swift build` exit 0, and
  its behaviour test runs, health-core 69/69).
- `appGroupStore` splits selection:
  `#if canImport(CoreFoundation)` →
  `ReadinessWidgetStore(defaults: ReadinessWidgetAppGroupDefaults(appGroup: appGroup))`;
  `#else` →
  `ReadinessWidgetStore(defaults: ReadinessWidgetFallbackDefaults(appGroup: appGroup))`.
- **No silent iOS behaviour change**: on Apple platforms the selected
  accessor, the CF calls, the App Group domain (`group.com.jirathip.sendlog`),
  the key (`sendmeter.readiness-widget.snapshot`) and the plist schema are
  identical to round 0. The wiring pin **additionally** pins the guard line
  and the Apple-side selection expression, so a future change cannot quietly
  route Apple platforms through the fallback; both new assertions bite at the
  pre-fix contract (RED receipt below).
- Public API unchanged: `ReadinessWidgetDefaults` protocol,
  `ReadinessWidgetStore` API, non-optional `appGroupStore`, domain/key/schema.

## The Linux fallback

New `ReadinessWidgetFallbackDefaults.swift` — Foundation-only, compiled on
every platform (not `#if`-gated) so it is exercised by the host tests instead
of only assumed for Linux:

- wraps `UserDefaults(suiteName: appGroup)`;
- save → load round-trips; a second store over the same domain sees the same
  bytes;
- reads as `nil` when nothing is stored, and a suite that could not be
  created at all (`init(defaults: nil)` seat) degrades to nil reads and
  no-op writes — never a crash, never a fabricated value;
- on Linux there is no cfprefsd and no App Group container, so the suite-API
  refusal this issue is about does not exist there; the accessor preserves
  the store contract and is never selected on Apple platforms.

## Linux verification — what was and was not run (no fabrication)

- **Not run here: an actual Linux compile.** No Linux toolchain/SDK is
  installed (`swift sdk list` → none; toolchain is Apple Swift 6.3.3,
  arm64-apple-macosx26.0). The Docker CLI exists but no daemon is running
  (`/var/run/docker.sock` absent); no colima VM, no podman/nerdctl — starting
  one is a host-level change this lane does not make.
- **Static guarantee** (`docs/evidence/issue-991/fix1-linux-static-guarantee.txt`):
  in comment-stripped contract code every CF-symbol reference sits inside the
  `#if canImport(CoreFoundation)` block (or is the guard directive itself);
  the `#else` selection line and the entire fallback file's code contain zero
  CF symbols; the module imports Foundation only (all 9 files).
- The authority for the Linux compile remains the hosted `package-tests` job
  at this head.
