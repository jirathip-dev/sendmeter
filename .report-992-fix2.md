## F2R-1 — the missed site, raised; and the method fix

the submit catch at `:54-56`): it set `lastSubmittedAt = nil` and nothing else —
a rejected BGTaskScheduler submit left no trace, so a device that never
re-arms its background sync could not name why. It now emits


off-main from BGTask handlers and the task-registration path, and the emission

nil` still, the handler still completes).

## F2R-2 — the production emitter's *output* is witnessed now

**Mechanism** (`Sources/Core/PersistedFailureLog.swift`): `emit` records every
line it carries into a bounded, lock-guarded **emission audit ring** — the
observation point. API: `PersistedFailureLog.recentEmissions(limit:)` and
`emissionCount()`. The production binding and every direct emit call record
there, so a test can drive a **real** failure through the **unsubstituted**
production path and read back what was emitted.

**Witnesses (two, CI-run at different layers):**

1. `PersistedFailureLogTests.testProductionSinkEmissionReachesTheAuditRing`
   (host suite — runs in the `Core tests` CI job via `scripts/swift-coverage.sh`):
   drives `PersistedFailureSink.production(line)` and asserts the emission count
   advanced and the line is in the ring.
2. `PersistedFailureLogAppTests.testRealFailureThroughTheProductionSinkReachesTheAuditRing`
   (app-target suite — runs in the `iOS Simulator build` job's
   `-only-testing:SendmeterNativeTests` step): builds a real `AppModel` with the
   default sink (no substitution, asserted), drives the offline refresh, and
   asserts the `refresh-slice:sessions` line (level `.notice`, domain/code/
   class/surfaced) is in the ring.

Both are additional to the kept round-1 identity witnesses.
