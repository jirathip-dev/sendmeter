## 2. Root cause — the fixture, not production (`file:line`)

The retry test drove `health_metrics` and `climb_workouts` through their
**first-sync display window** and then asserted the **paged reader's** results.
Both entities branch on the cursor before the paged reader ever runs:

- `native/SendmeterNative/Sources/Data/Repositories.swift:2065`
  (`fetchHealthMetricDelta`, `:2061-2082`): `guard cursor != nil else { … }` —
  `since: nil` issues **one** request,
  `select=…&order=date.desc&limit=60`, no cursor filter, no
  `Prefer: count=exact`, and returns through `makeDelta`.
- `native/SendmeterNative/Sources/Data/Repositories.swift:2153`
  (`fetchWorkoutDelta`, `:2149-2170`): the same shape,
  `order=started_at.desc&limit=30`.
- `native/SendmeterNative/Sources/Data/Repositories.swift:2307` (`makeDelta`):
  the window's checkpoint is `rows.map(updatedAt).max()` — a **bare**
  `LocalCacheStore.syncCursorString`, no `|entityID` suffix.

That is exactly what both the hosted job and my local RED observed: one row
served (the newest by `date`/`started_at`), a checkpoint of
`2026-01-21T12:54:20.000000Z` with no tie-break, and zero re-serves — while the
test expected the `(updated_at, <tie-break>)`-ordered `DeltaPageReader` read
(three rows ascending, a composite checkpoint, and the mutated row re-served by
the following page).

The expectation was **unreachable** for those two entities at `since: nil`, and
it is not a CI-only or simulator-state split: it reproduces deterministically
at `7b97d72` on a fresh simulator, which is why the hosted runner failed too.
The window itself is a **protected product decision**: AC5 is "No schema
rewrite **or production row-limit change**", the lane's sibling test pins the
windows, and `AppModel` passes `cacheCursor(accountUserID:entityType:)`
(`Sources/App/AppModel.swift:2618`, `:2622`) — so `nil` only ever happens on a
genuine first sync, and the retry/re-serve path is the cursor-bounded one.

## 6. The actual serving model (what the fix now encodes)

| entity | `since: nil` | `since: <cursor>` |
|---|---|---|
| `user_settings`, `phase_periods`, `tindeq_presets`, `routine_presets`, `tindeq_tags` | paged reader, `(updated_at, <tie-break>)` asc, 500/page, `Prefer: count=exact`, composite checkpoint | same |
| `health_metrics` | **one** window request `date.desc&limit=60`, no cursor filter, bare newest checkpoint | paged reader, `(updated_at, date)` |
| `climb_workouts` | **one** window request `started_at.desc&limit=30`, no cursor filter, bare newest checkpoint | paged reader, `(updated_at, id)` |

`AppModel` hands the two window entities their cached checkpoint on every
refresh after the first sync, so the paged reader is their live path; the
first-sync window is the display decision the issue freezes. The retry fixture
now mirrors that split instead of contradicting it, which is the whole fix.
