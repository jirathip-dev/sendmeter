## Redaction / PII statement

The line carries ONLY: the channel (fixed enum), the level (fixed), the
operation label (written in code — e.g. `refresh-slice:sessions`,
`queue-upload:preset`, `watch-transmit`), the error DOMAIN and CODE from the
bridged `NSError`, the `FriendlyErrorClass` name (the taxonomy's own word), and
the `surfaced` boolean. **No** messages, payloads, tokens, session identifiers,
email addresses, URLs, user ids or content. The builder takes an `Error` and
never `localizedDescription`; queue/step labels are fixed case names, never
entity ids or names (the queue line uses `PendingWrite`'s case label, not the
payload). All interpolations are `privacy: .public` because they contain only
non-sensitive identifiers — the #964 round-2 stance, kept.

  lane's wrapper serializes on `/tmp/sendmeter-xcodebuild.lock` with the herdr
  mkdir-lock shim (owner.pid, quarantine-then-inspect reaping, pgrep gate,
  45-minute bound, release on every path). While this lane ran, the
  `impl-1004-lock` lane used the SAME lock path with a **different, ownerless
  protocol** (`mkdir`/`rmdir` polling, no owner.pid): its empty dirs looked
  stale to the shim's reap logic, and its `rmdir` couldn't remove a dir the
  shim owned. Nothing broke (the pgrep gate inside this lane's wrapper is the
  real serialization), but the orchestrator should know two lanes can hold
  "the lock" in different formats. Observed: ownerless dir age 96–143 s while
  a sibling build ran lockless; `flock[20011]` reaped only after its 150 s
  grace and then waited out the sibling via pgrep.

  through this lane's runs; every one of this lane's builds waited for
  `pgrep -x xcodebuild` to be empty first (log lines with timestamps in the
  gate logs).
