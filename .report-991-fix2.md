## Round 1's claim, retracted

`.report-991-fix1.md` (and `fix1-linux-static-guarantee.txt`) asserted:
_„`canImport(CoreFoundation)` is false on Linux: the original CI failure
itself is the evidence"_. **That was wrong.** The raw `package-tests` log at
head `2acdf482` (run 37203412812, job 111439538188) shows the Linux
`swift:6.3` container compiling the guarded block: 80 `cannot find` errors at
`ReadinessWidgetContract.swift:182-209` (`CFString`, `CFPropertyList`,
`CFPreferencesCopyValue`, `CFPreferencesSetValue`,
`CFPreferencesAppSynchronize`, `kCFPreferencesCurrentUser`,
`kCFPreferencesAnyHost`). Linux's swift-corelibs-foundation ships a
`CoreFoundation` module — a **subset** without those symbols — so the
module-availability condition was true where the full API did not exist.
Round 1's guard, its evidence claims, and its truth-table row are superseded
by this round; the round-1 files remain unchanged as the record.

## The guard (both sites) and why

```swift
#if os(macOS) || os(iOS) || os(watchOS) || os(tvOS) || os(visionOS)
```

- Site 1: `ReadinessWidgetAppGroupDefaults` (the CFPreferences accessor) —
  compiled only under this guard.
- Site 2: `ReadinessWidgetStore.appGroupStore` — selects
  `ReadinessWidgetAppGroupDefaults` under the guard, the suite-backed
  `ReadinessWidgetFallbackDefaults` in the `#else`.

Why this form: round 1 failed because a **module-availability** condition
silently evaluated true on Linux. `os()` is a **target-triple** condition —
a Linux build is `os(Linux)`, which none of the five alternatives names, so
the Apple branch is unreachable there **by construction**, regardless of what
modules any toolchain ships. (`#if !os(Linux)` alone was not used — the brief
forbids it and it would silently drop e.g. Windows; `canImport(Darwin)` was
not used because it repeats the availability-assumption class that already
failed once.) The five names cover every platform that compiles this module:
the iOS phone app, the watchOS watch app, macOS host tests, plus tvOS and
visionOS for completeness.

## Linux verification — what could not be run here (no fabrication)

No Linux toolchain/SDK is installed on this host (`swift sdk list` → none;
toolchain is Apple Swift 6.3.3, `arm64-apple-macosx26.0`), and the Docker
daemon is not running — so the Linux compile is not executed locally. The
static property for Linux is structural this time: the only code the Linux
compiler will see in these two places is the `#else` branches (no CF
symbols; exact selection line quoted in `fix2-guard-truth-table.txt`), and
the fallback file's comment-stripped code contains zero CF-symbol references.
The hosted `package-tests` job at this head is the authority, read and quoted
above.
