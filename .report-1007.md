## 0. TL;DR

**Premise verdict: (a) — falsified.** The Watch app does **not** ship a retired publishable key. The shipped
device/Release watch reads `Resources/SupabaseConfig.plist`, whose `SUPABASE_ANON_KEY` is **byte-identical**
to the phone's `SupabaseConfiguration.publishableKey` (`sb_publishable_eHRHTels…`). The
`sb_publishable_ACJWlzQHlZjBrEguHvfOxg_3BJgxAaH` literal exists **only** inside the
`#if DEBUG && targetEnvironment(simulator)` branch, which points at the **local** stack
(`http://127.0.0.1:54321`) — and the value is the Supabase CLI's **fixed local-development publishable key
constant** (`defaultPublishableKey`, supabase/cli#4167), **not a key of this (or any) hosted project**. There
is therefore **nothing to revoke** (AC5: recommendation below).

The real, fixable defect the issue's framing exposed: **nothing tied the two committed keys together, and
nothing tied the simulator literal to the local-stack key.** A rotation that updated one file and missed the
other would have been invisible until a device failed. This lane ships the guard that makes both drifts fail
`just core` (and CI), plus the gitleaks allowlist entry for the new exact form.

## 2. Deliverable

### 2.1 The genuine fix

The premise is (a); per brief §2.1 the fix is the **divergence guard** plus verifying the simulator literal.
The literal needed **no change** — it is byte-identical to the CLI's fixed local-development key (1.3). What
was missing is enforcement. Shipped:

1. `native/SendmeterNative/Tests/SendmeterCoreTests/PublishableKeyParityTests.swift` — 3 host-side wiring
   tests (the lowest layer that can express this; they run on every `just core` and in CI via
   `scripts/swift-coverage.sh` in `native-swift.yml`'s `core-tests` job):
   - **phone key == Watch bundled plist key** (and both are `sb_publishable_`-shaped, and the shipped key is
     never the local-stack key);
   - **Watch simulator branch key == the CLI's fixed local-development key** (the sim literal cannot drift
     from the local stack again) and still points at `http://127.0.0.1:54321`;
   - **phone URL == Watch plist URL** (same-project guard).
2. `.gitleaks.toml` — one new allowlist block for the exact new assignment form (hex-escaped value, anchored
   line regex, same `targetRules`/`paths` shape). **No existing regex was loosened or removed**; the existing
   allowlist blocks are byte-unchanged.

**Single-source-of-truth option was evaluated and not taken**: the phone consumes a **compiled Swift
constant** (`native/SendmeterNative/Sources/Data/SupabaseService.swift:12`) while the watch consumes a
**bundled plist**; one shared resource would re-plumb the phone target (resource wiring + initialisation
path) for no stronger guarantee than the gate the brief allows as the fallback. The brief's fallback is
therefore the delivered enforcement; it runs at the same layer as the repo's other source-text wiring
guards (`SplashPresentationWiringTests` and friends).

### 2.4 Why the two diverged (AC2) — deliberate split, never a rotation

Raw receipts: `docs/evidence/issue-1007/divergence-history.log`.

- The Watch plist's hosted value has existed since the file's introduction (`e1d313d`, 2026-07-13, "Migrate
  the watch app into a true iOS companion target") and has **never changed** since.
- The simulator literal arrived with `03c861d` (#95, 2026-07-22, "Local dev environment: local Supabase
  stack, seed, and simulator wiring") — the commit that deliberately pointed the simulator at the local
  stack. The plist was **not** touched by it.
- `git log -S` shows the local value never appears in the plist or the phone file, and the hosted value never
  appears in the watch service — they were never the same variable to rotate. **Verdict: deliberate
  environment split** (sim → local stack, device/Release → hosted project), exactly as the code comment in
  `SupabaseService.swift` says ("only the simulator gets pointed at the local Supabase stack").
- **No other bundled constant is stale in this way**: `mcp/src/config.ts` defaults to the same hosted URL +
  key; every `zznsqmcewtzlnfoiefkk`/`mjkndfhjnipomjjhgsxv` occurrence checked is consistent with its
  environment (committed-surface sweep at HEAD in the same log).
