### The change

1. **Dismiss control.** The glyph keeps its top-trailing seat inside a fixed
   `44×44` frame with `contentShape(.rect)`, gets an explicit user-facing
   `.accessibilityLabel("Dismiss error")`, and a stable identifier
   (`error-banner-dismiss`). The 44 pt constant lives next to the label in
   `ErrorBannerAccessibility`.
2. **Full wrap.** The message `Text` gets `fixedSize(horizontal: false, vertical: true)`,
   so a compressed proposal can no longer truncate the copy at any text size. The
   decorative alert glyph leaves the accessibility tree (`accessibilityHidden(true)`).
3. **Announcement policy.** `ErrorBannerAccessibility.shouldAnnounce(previous:next:)` +
   `ErrorBannerAnnouncementModifier` (attached in `RootView` where the message value is
   observed) post **one** `AccessibilityNotification.Announcement` per NEW message through
   the injectable `post` seam. Announcements speak without moving VoiceOver focus; the
   banner carries no focus modifiers. Rerenders of the same message and dismissal are
   silent.
4. **Evidence harness.** `--error-banner-fixture short|long` renders the REAL `ErrorBanner`
   in the same top-overlay stack `RootView` builds (same spacing, same 16 pt horizontal /
   8 pt top padding, same transition) over the real signed-out screen, using the real
   `FriendlyError` copy: short = "Couldn't save this. Try again."; long = the longest
   message the app can surface ("Your iPhone's date and time may be wrong. Turn on Set
   Automatically in Settings → General → Date & Time, then try again."). DEBUG-only,
   launch-argument gated, never reachable from the normal flow.

## Acceptance criteria

### AC1 — explicit label + effective target ≥ 44×44 pt; hit region never obscures adjacent actions — **PASS**

- `testDismissRowReservesTheFullTargetHeight` renders the production banner at the
  production width (375 − 2×16 = 343 pt) via `ImageRenderer` and asserts the banner
  reserves a `12 + 44 + 12 = 68` pt row; raw run green in
  `~/impl927-gates/app-test-native-suite2.log` (`Executed 5 tests, with 0 failures`,
  `** TEST SUCCEEDED **`, exit 0).
- RED proof (probe P1, `~/impl927-gates/probe-p1-target-shrink.log`, raw exit 65): with the
  dismiss frame mutated back to a caption-sized 20 pt, the same test reports
  `("45.0") is less than ("68.0") - the banner must reserve a 44 pt row for the dismiss
  target (rendered 45.0 pt)` — i.e. the pre-fix geometry measures 45 pt and fails.
- The label and the target are one constant each
  (`ErrorBannerAccessibility.dismissLabel` / `.dismissTarget`); `testProductionWiringPins`
  fails if the control stops applying them (P1 also trips that pin).
- Hit region bounded: the target is its own `44×44` layout slot inside the banner's
  `12` pt padding (the message column is a sibling with `12` pt spacing, so no adjacent
  action can sit under it), and the banner's own overlay shape stays the rounded
  rectangle — the existing `StructuralHapticsWiringTests` pin (`.contentShape(RoundedRectangle…))`
  present, `.contentShape(Rectangle())` absent) is green in the same suite run.

### AC2 — long text wraps without clipping, smallest phone, normal AND accessibility sizes, light and dark — **PASS (with a disclosed overflow, below)**

- `testLongMessageWrapsWithoutClippingAtBothTextSizes` renders short and long messages at
  `.large` and `.accessibility5`, light and dark, and asserts the long copy adds
  ≥2 subheadline lines at normal size and ≥6 lines at accessibility size (a clipping
  implementation adds none), that dark mode adds no difference, and that the wrapped
  banner stays at the 343 pt phone width. Green in the suite run above.
- RED proof (probe P2, `~/impl927-gates/probe-p2-clip-one-line.log`, raw exit 65): with
  `.lineLimit(1)` on the message, the test fails
  `("68.0") is not greater than ("130.70…")` and `("92.0") is not greater than
  ("495.04…")` — i.e. clipping collapses the long banner to the short one's height.
- Screenshots (raw `xcrun simctl io … screenshot`, exit 0 for all 8, capture log
  `~/impl927-gates/capture2.log`): `docs/evidence/error-banner-927-{short,long}-{normal,ax}-{light,dark}.png`
  (sha256 in `~/impl927-gates/evidence-sha256.txt`). Inspected pixel-wise: at normal size
  the long copy wraps to 5 lines with **no ellipsis** and the dismiss control sits at the
  top right; the AX5 short case fits on screen with the message and control fully visible;
  dark captures show the same layout on the dark banner.
- **Disclosed overflow (not a truncation):** at AX5 on this 375×667 phone the longest real
  message wraps to its full height (~15 lines) but extends below the bottom of the screen,
  because the banner is an unbounded top overlay with no scroll container. This is the
  pre-fix presentation property (this change adds 27 pt of row height, nothing else), the
  text is never truncated, and the close control stays on screen — but a user at the
  largest text size cannot read the end of the longest message. **Follow-up suggested:**
  cap the message area and make it scrollable. Recorded as an explicit gap, not claimed as
  fixed.

### AC3 — new actionable errors announced once; rerenders neither spam nor steal focus — **PASS (contract), focus by mechanism**

- `testNewFailureAnnouncesExactlyOnceAndRerendersStaySilent` (hosted harness using the
  production modifier with an injected `post`) proves the exact post list across
  nil → long → 5 unrelated rerenders → same value → nil → short → re-occurrence:
  `[]`, `[long]`, `[long]`, `[long]`, `[long]`, `[long, short]`, `[long, short, short]`.
  Green in the suite run; `testAnnouncementPolicyMatrix` pins the pure policy.
- RED proof (probe P3, `~/impl927-gates/probe-p3-announce-spam.log`, raw exit 65): posting
  at every render evaluation makes the rerender legs fail (6 failing assertions) — the
  test genuinely discriminates "announce once" from "announce per render".
- Focus does not move: the mechanism is an announcement (it speaks the text without
  touching VoiceOver focus), the banner path contains no `accessibilityFocused` /
  `accessibilityFocusState` (pinned), and nothing is presented modally. No focus assertion
  is machine-verified — VoiceOver is not scriptable headless (see "Not verified").
