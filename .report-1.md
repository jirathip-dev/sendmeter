## The serving model (which mechanism actually delivers the behaviour)

1. **What runs the check.** The new `docs-check` job
   (`native-swift.yml:119-168`), on the cheap Linux runner
   (`:121`, `blacksmith-4vcpu-ubuntu-2404` — the label four other
   workflows already use: `ios-ci.yml`, `mcp.yml`, `secret-scan.yml`,
   `supabase-tests.yml`, `native-testflight.yml`). Its last step is
   `run: bash scripts/check-docs-stale-commands.sh` (`:167-168`). There is no
   `|| true`, no `continue-on-error`, no wrapper: the script's exit status **is**
   the job verdict, so a violation turns the `Docs stale-command check` check
   red on the PR.
2. **What makes it automatic.** The doc surface is now in the workflow's path
   filters for both `pull_request` (`native-swift.yml:44-57`) and `push`
   (`:85-98`): `CLAUDE.md`, `AGENTS.md`, `README.md`, `DESIGN.md`,
   `FINDINGS-663.md`, `PERF-671.md`, `RELEASE_NOTES.md`, `.report-*.md`,
   `docs/**`, `justfile`, `.agent/config.yaml`, `.claude/launch.json`,
   `ios/debug.xcconfig`, `scripts/check-docs-stale-commands.sh`. `.report-*.md`
   is in that list because every lane PR carries one, so a docs-only lane PR
   (report + `docs/evidence/**`) is on the surface too.
3. **What keeps a docs-only PR cheap.** The `docs-check` job is also the
   classifier: the `Classify the change surface` step (`:131-166`) diffs the PR
   base against the checked-out head and publishes `native` as a job output
   (`:123-124`). The two heavy jobs carry
   `needs: [docs-check]` + `if: ${{ !cancelled() && needs.docs-check.outputs.native != 'false' }}`
   (`:175-176`, `:233-234`), so they run for every diff that is not docs-only
   and skip only a positively-classified docs-only diff. Nothing they do
   changes; a diff they run for today still runs them. The classifier job
   itself runs on every triggered run — that is the only cost a native PR pays
   for this wiring (a Linux checkout plus the text scan).
   The classifier **fails closed**: a manual dispatch, a new branch's all-zero
   `before` sha, an empty diff, or a base the clone cannot resolve all leave
   `native=true` (the pre-#944 behaviour). A path missing from its
   `docs_surface` regex is likewise classified native — an omission costs a
   native run, never a skipped one.
4. **What deliberately does NOT serve it.** (a) The script's rules: no
   `RETIRED` pattern, no `CURRENT_FILES` entry and no allowlist entry was
   relaxed, added or removed — the only script delta is a header comment
   (`:11-16`). (b) `just fast` deliberately still runs `slop` + the three
   SwiftPM suites only, so `CLAUDE.md`'s description of `fast` stays exactly
   true; the new recipe is `just docs-check` (added, `justfile:44-45`) and
   `just ci` now lists it first (`justfile:91`), because that recipe's own
   comment claims it is "Everything CI gates on". (c) `ios-ci.yml` is
   untouched — it still triggers on `scripts/**` and still does not run the
   docs check; wiring the same check there was out of fence.
