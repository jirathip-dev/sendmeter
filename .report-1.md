### The actual serving model (runtime mechanism)

Both issues are served by **one new Core derivation plus a per-slice refresh
coordinator**, not by a view-local count:

- Pending/sync status: `MutationSyncStatus.resolve(_:)`
  (`Sources/Core/MutationSyncStatus.swift:135`) is the only place that turns
  the account's acknowledged answers — `hasLoadedPendingWrites` (the queue file
  and its quarantine list have actually been read: `AppModel.swift:412`,
  published in `refreshQueueCount`), `queuedWriteCount`, the cache's pending
  row count, `quarantinedWrites` and `lastRetryOutcome` — into one of
  `notLoaded / synced / awaitingUpload / needsAttention` plus the retry
  availability. `SettingsView` (`SettingsView.swift:510`) and
  `TagManagerView` (`TagManagerView.swift:56`) render that value; neither
  counts anything itself any more. **The dismissible banner is not load-bearing
  for either issue** — the status row is.
- Refresh slices: `AppModel.refreshAll` fetches all nine slices into
  `SliceFetch` outcomes (`AppModel.swift:2642`/`:2655`), folds them into
  `RefreshSliceOutcomes` (`Sources/Core/RefreshSlicePlan.swift:93`), applies and
  publishes only groups whose every slice succeeded
  (`AppModel.swift:2915`–`:3010` reconcile gates, `:3049` the single
  publication), and records the scoped failure via `recordPartialRefresh`
  (`AppModel.swift:2694`). The account-wide freshness stamp is advanced only by
  `outcomes.didFullyRefresh` (`AppModel.swift:3071`).
- What deliberately does **not** serve them: the global error banner (a partial
  failure with published slices is suppressed on purpose:
  `Sources/Core/ErrorSurfacePolicy.swift:48`) and the automatic backoff drain
  (a cache-only residue has no queue entry, so only the explicit
  `retryAllQueuedWrites` preflight `adoptLegacyResidues`
  (`AppModel.swift:7150`) reaches it).
