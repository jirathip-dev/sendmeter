## What was extracted (and what deliberately was not)

New Core owner: `native/SendmeterNative/Sources/Core/MutationRecoveryCoordinator.swift`.

- `MutationRecoveryQueuing` (`:17`) is the queue seam. Production has **exactly
  ONE conformance** — `extension DurableQueue: MutationRecoveryQueuing` (`:86`),
  i.e. the app's single `pending-writes.json` — so no second queue, no second
  persistence format and no competing drain timer can appear behind the app's
  back. The seam exposes only the queue's own primitives (due/active/quarantined
  reads, `markFailure`, `retryQuarantined`, `requarantine`,
  `discardQuarantined`).
- `MutationRecoveryCoordinator` (`:363`) owns the pass rules: `drain` (`:386`,
  also the sign-out shape), `retryAll` (`:459`), `retryOne` (`:518`),
  `recordFailure` (`:582`), `retryQuarantined` (`:629`),
  `discardQuarantined` (`:687`).
- Injectables: the account boundary is the SAME `WorkspaceAccountBoundary` #934
  introduced (`WorkspaceSyncCoordinator.swift:166`) — one account fence in the
  app, not two; the queue, the payload-specific uploader, the per-entity residue
  adopters, the claim/wait primitives and the acknowledgement publication are
  all passed in per call.

## The actual serving model

The behaviour is served by, in order:

1. `AppModel.drainQueue` / `drainQueueForSignOut` / `retryAllQueuedWrites` /
   `retryQuarantinedWrites` / `discardQuarantinedWrite` compose
   `MutationRecoveryCoordinator` (Core) — the passes' sequencing, fences and
   policies live there and nowhere else;
2. the coordinator drives the app's SINGLE `DurableQueue<PendingWrite>`
   (`pending-writes.json`) through `MutationRecoveryQueuing`, whose only
   production conformance is that queue;
3. the queue itself serves the durable semantics: revision-fenced writes,
   `retryDelay(attempts:)` backoff, the permanent-attempt budget
   (`maxPermanentAttempts == 3`), the quarantine stamp, ordering by
   `(nextAttemptAt, createdAt)`, and removal-on-upload;
4. the payload-specific network call, the cache confirmation and the optimistic
   UI are served by `AppModel.upload` (injected into the pass as a closure), and
   the acknowledgement publication is served by `AppModel.refreshQueueCount`.

Deliberately NOT serving it: `isRetryingQueuedWrites`/`lastRetryOutcome` are
publications (the gate in Core decides ownership), `quarantinedWrites` is a
projection of the queue's quarantine list, and the per-entity residue adopters
stay in `AppModel` because each entity's residue has its own server-anchored
adoption rule (#916–#919).
