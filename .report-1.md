## What this change is

One explicit owner for the manual-workout lifecycle.

`SendmeterCore` gains `ManualWorkoutLifecycleCoordinator`: it **holds the in-progress
workout** and decides start / minimize / resume / attempt transitions / End, hands the
accepted finish over as **one draft + ticket** to persist, and returns the rest /
live-card effects as **values**. The clock (`at date:`), the rest target, the effects
and the save's completion ticket are all inputs — the type imports only `Foundation`.

`AppModel` holds the ONE instance (`manualWorkoutLifecycle`) and is the only applier of
its effects (`applyManualWorkoutLifecycle`); `WorkoutView` and
`ManualWorkoutFullscreen` now READ the workout from the owner instead of keeping it in
`@State`, so a recreated view resumes the running workout instead of recreating or
silently terminating it. The durable save still goes through `saveWorkout` → the ONE
pending-writes queue → the #935 `MutationRecoveryCoordinator` (no second path, no
second persistence format, no schema change, no new scheduler).

pure math, the STOP/FINISH circle, and the one pending-writes queue. `ManualWorkoutActivityContent.swift:79`
documents the one truth that moved (the workout is no longer `@State`).

## What I did NOT verify (OPEN)

- **Device-only legs stay OPEN** (never claimed): the Live Activity card's actual
  rendering and lock-screen intents (ActivityKit does not render in the simulator and
  `ActivityAuthorizationInfo().areActivitiesEnabled` is false there), the rest-over
  local notification delivery and its permission prompt, the Apple Watch mirror of a
  manual workout, and a real climb on hardware.
- **The app-level *application* of the card/rest effects is not directly observable
  in the simulator** (the ActivityKit adapter is inert there, and the rest scheduler
  exposes no readable state). This lane proves the effect PAYLOADS deterministically in
  Core and proves the durable consequence (the save) at the app layer; it does not
  prove a rendered card or a fired notification locally.
- **Backgrounding**: no test suspends the app with a workout in progress. The workout is
  process-lifetime state on the owner (no presentation-scoped copy), `minimize` is
  proven by the UI suite, and `ManualWorkoutRestScheduler.scenePhaseChanged` is
  unchanged — but no background scenario was executed.
- **Hosted CI**: not run from this lane (no GitHub mutation); the orchestrator owns the
  hosted run at the pushed head.
- **The pre-existing #978 family did not reproduce** on the recorded run (155/0 after
  an app uninstall; it DID fail on the earlier freshly-erased run). Both raw runs are
  committed and neither was retried into green.
- **`just fast`'s documented #956 hang class did not fire** in either attempt.
- **`DESIGN.md:174-175`** cites `Sources/Features/Workout/WorkoutView.swift:104-110` for
  the full-screen execution surfaces; the two covers now sit at `:113`/`:117` (they were
