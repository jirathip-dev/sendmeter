## What was broken (source-confirmed at the base sha, not device-reproduced)

1. **Producer half (phone → watch).** `WatchConnectivityService.publishReadiness(_ metric:)` emitted a
   flat dictionary `{kind: "readinessResult", date, computed_at?, readiness?, zone?}`.
   `ReadinessRefreshResult.init?(message:)` requires a non-empty `requestId` **and** a decodable
   `status`; `ReadinessApplicationContext` additionally requires an `accountUserId` stamp
   (`resultBelongsToAuth`). So **every phone push was dropped twice over** — the watch's
   `ReadinessManager.receive` could never decode one, and the account-scoped context merge refused to
   store one.
2. **Consumer half (watch → phone).** `WatchConnectivityService.handle(_:replyHandler:)`'s
   `switch kind` had no `readinessRefresh` case, so a watch ask — the immediate `sendMessage` and the
   queued `transferUserInfo` fallback — fell through to `default: replyHandler?([:])`: an empty
   acknowledgement. `ReadinessManager` could not decode it and, after its 6 s timeout, showed
   "Offline · showing cached" with no typed reason. (The phone-side handler for #520 lived in the
   Capacitor plugin retired by #857 and was never ported into `native/SendmeterNative`.)

## Acceptance criteria

### AC1 — a real phone-produced result round-trips with score/freshness/status/timestamps/identity — **PASS**

- `ReadinessWatchBridgeTests.testWatchAskRoundTripsThroughTheBridgeIntoTheWatchResultGate`: a request
  built by the production `ReadinessRefreshRequest.message()` + `WatchBuildReport.stamped(...)` goes
  through the bridge; the answer is decoded with the production `ReadinessRefreshResult(message:)` and
  asserted field-by-field — `requestId`, `reason`, `sentAt` (the watch's send point), `status`,
  `freshness`, `startedAt`/`completedAt`, `accountUserId`, and `snapshot`
  (`date`/`readiness`/`zone`/`computedAt`). The production watch gate
  (`ReadinessResultGate.shouldApply`) accepts it for the requester's account and rejects it for
  another account.
- `WatchReadinessDispatchAppTests.testPhoneRecomputePushIsATypedResultInsteadOfTheLegacyFlatDictionary`:
  the phone's own recompute push decodes through the same decoder with `status`, `freshness`,
  `accountUserId` and the score intact, and the pre-#913 flat keys (`computed_at`/`readiness`/`zone`)
  are gone from the wire.
- `ReadinessWatchBridgeTests.testPhonePushDecodesThroughTheWatchGateAndKeepsTheSignedInContext`: the
  push merges into the signed-in relay through the production `ReadinessApplicationContext` (auth keys
  survive) and is applied by a watch with **no** active request because it is account-stamped.

### AC2 — immediate **and** queued asks reach the native handler; typed outcomes, never an empty ack — **PASS**

  `testImmediateAskIsAnsweredWithAPublishedTypedResult` — reply is non-empty, decodes as

## Deliberate decisions / judgement calls

- New logic lives in `SendLogWatchCore` (shared, Foundation-only, host-testable) because the brief
  requires using the existing shared request/result types, and because the repo convention is "the
  service stays a dumb transport". The phone's `WatchConnectivityService` only routes and delivers.
- The phone's merge now uses the shared `ReadinessApplicationContext` state machine it was written for
  ("shared with the phone bridge") instead of a raw dictionary merge — so a readiness result can no
  longer replace the auth relay, and an account-mismatched result is dropped. A push with no known
  account is skipped (`guard let activeAccountUserID`), and an empty merged payload is never
  transmitted (it would blank a persisted context).
- `freshness` on the push is the pass's own decision: a today-upsert that carries a readiness was a
  fresh compute (`.fresh`); the kept-score branches re-upsert biometrics with readiness nil
  (`.cached`). A coalesced pass that produced nothing answers `.cached` with a nil snapshot, so the
  watch keeps showing its last known score rather than being blanked.
- A message with `kind == "readinessRefresh"` but **no** request identity returns `nil` from the
  bridge (the transport's existing empty ack applies): an answer the watch cannot match to an
  in-flight ask must not be invented, and `requestId` is the only join key.
- `handle` and `pendingApplicationContext` are internal (not public) **only** so app-target tests can
  drive the real dispatch without a paired watch; production callers are unchanged.
