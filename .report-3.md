## Blocker 1 — `("40.666666666666664") is not equal to ("40.5")`, line 60

**Disposition: reproduced, environment-dependent test constant — fixed by
deriving the value, assertion kept.** The resolved `caption2` size at
`.accessibility5` is **display-scale dependent**, measured on the same code:

| device | scale | resolved caption2 @.accessibility5 |
|---|---|---|
| iPhone SE (3rd gen) | 2× | **40.5** pt |
| iPhone 17 | 3× | **40.666666666666664** pt |

40.666… on the 17 is bit-for-bit the hosted number, so the pin — a literal
`40.5` the arithmetic was written against — could never hold on CI.

**Change** (`TrainingLoadAxisLegibilityTests.swift`): `accessibilityPointSize`
is now resolved from the same `UIFontMetrics(forTextStyle: .caption2)
.scaledValue(for: ChartAxisLabelRule.basePointSize, compatibleWith: traits)`
source the view's `@ScaledMetric` reads, so every expectation built on it is
environment-independent. The line-60 assertion is **kept and re-aimed**: a
`±0.5 pt` tolerance against the `40.5` anchor, justified in the message — the
closest AX5 decision boundary ("Now" vs its 71.75 pt column, margin **9.65 pt**)
cannot flip inside ±0.5 pt, while a larger drift means the arithmetic and its
printed evidence need a re-check. Diagnostic strings now interpolate the
resolved value instead of naming 40.5.

## Blocker 2 — `ax5: labels true, readout true` (line 336)

**Disposition: the failure is real and reproducible, but the defect is in the
lane's own pixel detector, not in the product — proved from the pixels before
touching anything.**

The 3× AX5 hosted render (`render-ax5-hosted-3x.png`, written by the failing
test itself) contains **no value labels** and **does contain** the four-line
exact-values readout. The row map of that image:

| rows (px) | what |
|---|---|
| 780–1043 | title (wrapped, 2 lines) |
| 1146–1231, 1325–1428 | delta chip, two lines |
| **2522–2713** | **the bars** (192 px = 64 pt) |
| 2756–2842 | week captions (thinned: `3w 2w 1w`) |
| 2951–3602 | the readout, four lines |

The product state is exactly what the rule says at AX5 on that width: every
value label is omitted by column fit and the readout carries the values. The
**delivered detector** anchored its "bars" on the first row with ≥200 coloured
pixels — a 6 px sliver at **1351**, the delta chip's glyphs — so its
"label window" covered the *header* (the title's text reads as labels ✗) and
its "readout start" landed below the real bars (readout ✓): one artifact plus
one truth, printed as `labels true, readout true`. Measured colour coverage
rules the chip out and the bars in: chip rows ≤ **0.18** of the width; the bars
**0.38–0.77**; the *true* bar band is the [2522, 2713] run.
Evidence: `diagnostic-old-anchor-row1352.png`, `render-ax5-chart-3x-crop.png`,
`diagnostic-readout-block.png`, and the profile printed in the fix commit.

**Change (tests, layer = the detector itself):**

* `coloredCounts` now counts `spread > 15` pixels (the card/backdrop are grey,
  ≤ 3; the bars' lightest gradient rows stay above 15) — validated against
  renders at **both** scales.
* The chart is anchored as **the longest contiguous run of rows whose coloured
  pixels cover ≥ 30 % of the rendered width** (bars: 77 % at four columns;
  chip text: ≤ 18 %) — no absolute pixel counts left, so the detector is
  scale-independent.
* New guard: if the detected band is taller than `1.5 × maximumBarHeight`, the
  probe **throws with the measured band and the limit** instead of feeding the
  assertions garbage. This is what the delivered detector lacked; it converts
  exactly this failure mode into a loud, diagnosable one. No assertion was
  weakened, no skip was added, nothing is special-cased for CI.

**Change (product, hardening — not the CI fix):** the width the readout's plan
resolves from now comes from a background `GeometryReader` attached to **the
chart's own box**, not the surrounding stack's. The two are not guaranteed to
agree — in the reviewed build the outer stack's reader reported **41 pt** while
the chart drew from **311 pt** (r1 instrumentation, `docs/evidence/issue-929-fix/diagnostic-marker-*.png`)
— and the readout now shares the chart's box, so the two plans cannot straddle
a fit boundary. Stated as hardening: no local reproduction of the CI failure
implicates the product, and the pixels say the product was coherent.

## Serving model (this head)

* The readout's plan width is served by the **chart-box background reader**:
  `Color.clear.onAppear { containerWidth = proxy.size.width }` +
  `onChange(of: proxy.size.width)` attached inside the chart's own
  `GeometryReader` — the same box the value/week plans are computed from.
* The state stays 0 until the first layout, so the readout is hidden, never
  guessed, before the chart has been laid out.
* The r1 finding still holds: a `PreferenceKey` channel is not serving the
  width on this platform (it delivered the placeholder value once and never the
  settled one) — no preference is used anywhere in this path.
