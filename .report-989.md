## The mechanisms (per-offender classification; (a) container/account coupling, (b) wall-clock race, (c) genuine intermittent product defect)

The suite runs in ONE simulator with ONE real app data container (`Library/Application Support/SendmeterNative/`). Three channels, all measured:

1. **(a) Fixed-identity account coupling.** Fixtures hardcoding an account id read rows the app persisted for that account in earlier runs/tests.
2. **(b) Snapshot reads racing a publish (model state).** Reads of `model.<published collection>` or an on-disk file immediately after an `await` that can still publish/hydrate.
3. **(b) Overlapping launch passes — `GuidedLaunchRecoveryAppTests`, read from the production shapes.** `makeSignedInModel` returns as soon as `currentUserID` is set, so the account bootstrap's own `refreshAll` (`AppModel:1976`) is still in flight when the test calls `refreshAll` itself. The bootstrap's full recordings reconcile tombstones every cached row the server snapshot does not carry — `payload='{}'` + `deleted_at` (`CachedWorkspace.reconcileServerDelta` → `LocalCacheStore.markDeletedDeltaServer`) — and the launch repair's quarantine requires `deleted_at IS NULL` (`LocalCacheRepair.quarantineInvalidRows`), so it legitimately publishes an **EMPTY report**. CI signature verbatim: `:115` `("0") is not equal to ("1")`, `:116` `("[]") is not equal to ("[SendmeterCore.LocalCacheEntityType.recordings]")`, `:117` `XCTUnwrap … QuarantinedCacheRow`, test time 0.767 s, `Executed 171 tests, with 3 failures` (run 37179622828 re-run @ `c3b72591`; log committed).
