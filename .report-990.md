### The mechanism, in code

`AppModel.refreshAll` (`native/SendmeterNative/Sources/App/AppModel.swift`):

- `:3278` — inside the publication closure that runs when the
  `sessionsAndRecordings` group published:
  `invalidateTagCurveCache()` — bumps every key's generation, cancels every
  warm task, and **clears `tagCurveCache` and `forceModel.tagCurves`**.
- `:3294-3312` — the re-warm is inside the *fully-successful sweep* branch:

```swift
if outcomes.didFullyRefresh {
    lastListRefreshAt = ProcessInfo.processInfo.systemUptime
    dashboardLoadFailureClass = nil
    lastPartialRefreshFailure = nil
    warmTagCurvesIfMissing(capturedBy: accountFetch)   // <- only here
} else {
    recordPartialRefresh(outcomes: outcomes, failures: sliceFailures, ...)
}
```

`outcomes.didFullyRefresh` is `!wasCancelled && failedSlices.isEmpty`
(`Sources/Core/RefreshSlicePlan.swift:136`) over all nine slices. So **any one
failing slice — health metrics, settings, routines, tags, workouts — empties
every fitted curve for the account and never rebuilds it**, while the
recordings themselves publish normally. The Force tab then shows the user's
exercise, PR and history with all four zone rows dimmed.

The curve cache is in-memory only (`AppModel.tagCurveCache`, `:805`) and every
authoritative refresh clears it, so the recovery paths are the ones *not* gated
on the full sweep: the background-sync publication
(`publishBackgroundSyncSnapshot`, `:7888`), the realtime slice reconcile
(`:11730`), and a save/edit/delete (`refreshTagCurvesForRPE`). Until one of
those runs, the state persists.

## The actual serving model (runtime mechanism) and lane identity

**Runtime mechanism that serves the observed behaviour** — the state the Force
tab reads is `forceModel.tagCurves`, published from `AppModel.tagCurveCache`
(`Sources/App/AppModel.swift:4945-4953`). What *sets* it is the warm funnel
`warmTagCurvesIfMissing` → `computeTagCurve` → `ForceCurveEngine.compute`, and
what *does not* set it is exactly one gate: `outcomes.didFullyRefresh` around

faithfully translate whatever the cache holds — that is why a *stale or empty*
cache is the only thing that can dim all four rows, and why the "No reference
curve" copy is a consequence, not a cause.
